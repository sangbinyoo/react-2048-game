# 2048 Game (React)

React의 핵심 훅(useState, useEffect, useReducer, useRef 등)과 커스텀 훅을 직접 체득하기 위해 만드는 2048 클론 게임 프로젝트입니다.

## 1. 목표

- 외부 상태관리 라이브러리(Redux, Zustand 등) 없이 React 기본 훅만으로 게임 상태를 관리한다.
- AI 도움 없이 로직(타일 이동, 병합, 랜덤 생성, 게임오버 판정)을 스스로 설계하고 구현한다.
- `useState`, `useEffect`, `useReducer`를 실제 동작 원리까지 이해하며 사용한다.
- 게임 로직을 `useGame2048` 같은 커스텀 훅으로 분리해, 컴포넌트는 UI 렌더링만 담당하도록 관심사를 분리한다.
- 전체 개발 기간 1~2주를 목표로, 단계별로 기능을 점진적으로 완성한다.

## 2. 관련 기술

- **React 18** – 함수형 컴포넌트 및 훅 기반 개발
- **Vite** – 프로젝트 스캐폴딩 및 개발 서버
- **JavaScript (ES6+)** – 배열/객체 불변성 처리, 2차원 배열 조작
- **CSS Grid / Flexbox** – 4x4 보드 레이아웃
- **CSS Transition** – 타일 이동/병합 애니메이션 (선택)
- **Git** – 버전 관리

## 3. 핵심 구현 항목

- [v] 4x4 보드 초기 렌더링
- [v] 랜덤 타일(2 또는 4) 생성 로직
- [v] 방향키 입력 처리 (`keydown` 이벤트 + cleanup)
- [v] 한 방향 이동/병합 로직 (좌/우/상/하)
- [v] `useReducer`를 활용한 게임 상태 관리 (보드, 점수, 게임오버 여부)
- [v] 점수 계산
- [v] 게임오버 / 승리(2048 타일 생성) 판정
- [ ] 커스텀 훅(`useGame2048`)으로 로직 분리
- [ ] (선택) 타일 이동 애니메이션
- [ ] (선택) 최고 점수 `localStorage` 저장

## 6. 학습 노트

### 컴포넌트 역할 분리의 어려움

처음에는 App.tsx 하나에 UI, 게임 로직, 상태 관리를 전부 작성했다.
기능이 늘어날수록 파일이 길어지고 어디서 무슨 일이 일어나는지 파악하기 어려워졌다.
UI는 컴포넌트로, 로직은 커스텀 훅과 유틸 함수로 분리해야 한다는 걸 머리로는 알았지만,
"이 함수는 state를 쓰니까 내부에 있어야 하고, 저 함수는 순수 계산이니까 외부로 뺄 수 있다"는
기준을 실제 코드에 적용하는 게 생각보다 쉽지 않았다.
결국 **state/props/훅을 참조하면 컴포넌트 내부, 그렇지 않으면 외부**라는 기준을 세우고 나서야 정리가 됐다.
커스텀 훅으로의 분리는 차후 개선 과제로 남겨둔다.

### 상태 관리 기준과 렌더 시점 이해

모든 값을 useState로 선언하다 보니 불필요한 리렌더가 발생했다.
**"이 값이 바뀔 때 화면을 다시 그려야 하는가"** 를 기준으로,
화면에 반영되지 않는 중간 계산값은 일반 변수로, 화면과 연동되는 값만 state로 관리해야 한다는 걸 배웠다.

또한 `setGameState`를 호출해도 state는 즉시 바뀌지 않고 다음 렌더 시점에 반영된다는 점에서
여러 번 막혔다. 이 때문에 업데이트된 값을 바로 다음 줄에서 참조하면 이전 값을 보는
stale closure 문제가 발생했고, 해결책으로 새로 계산한 값을 직접 인자로 넘기는 방식을 택했다.

`useEffect`의 의존성 배열과 `useCallback`을 조합해 이벤트 리스너가 항상 최신 state를
참조하도록 만드는 과정도 React 렌더링 흐름을 이해하는 데 큰 도움이 됐다.
